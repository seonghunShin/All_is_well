# All is well · 전체 React 프론트엔드

Ignav 항공편 조회에서 체험 예약까지 이어지는 React SPA입니다. 왕복 화면에서는 가는 편과 오는 편의 편도 운임을 각각 조회해 표시합니다. 계정, 좌석 선택, 결제, 관리자 운영은 브라우저에서 동작하는 시뮬레이션입니다.

## 실행

Node.js 22.12 이상 또는 24 LTS를 사용합니다. 프로젝트 루트의 `.env.example`을 `.env.local`로 복사하고 `IGNAV_API_KEY`를 설정합니다. Vite의 로컬 서버가 이 키로 Ignav에 요청합니다. 검색 결과 화면에서 예시 항공편으로 체험할 수도 있습니다.

```bash
npm install
npm run dev
```

개발 주소: http://127.0.0.1:5173

```bash
npm test
npm run build
npm run preview
```

프로덕션 미리보기: http://127.0.0.1:4173

Ignav 조회는 `dev`와 `preview`에서 동작합니다. 정적 빌드를 따로 호스팅할 때는 같은 출처의 `POST /api/flights/search` 서버 경로와 SPA fallback을 구성해야 합니다.

## 화면 구성

| 경로 | 화면과 기능 |
| --- | --- |
| / | 메인 검색, 왕복/편도, 공항·날짜·인원·좌석 등급, 여행지 선택 |
| /flights | Ignav 조회, 가는 편과 오는 편 순차 선택, 실제 결과의 항공사 필터, 운항 구간·기종·수하물 상세, 예시 항공편 전환 |
| /passengers | 인원수별 탑승객, 생년월일, 국제선 여권, 연락처 입력 |
| /seats | 검색에서 선택한 등급의 모의 좌석 배치도, 왕복 구간별 배정, 만료·선점 실패 체험 |
| /payment | 여정·좌석·총금액 확인, 결제 동의, 체험 결제, 실패·재시도 |
| /complete/:id | 예약 번호와 체험 예약 완료 |
| /bookings | 예약 상태 필터 및 목록 |
| /bookings/:id | 예약 상세, 취소 확인 및 취소 상태 반영 |
| /login | 체험 로그인 |
| /signup | 체험 가입, 비밀번호 확인 |
| /reset-password | 비밀번호 재설정 요청 화면, 발송되지 않는 안내 |
| /profile | 체험 회원정보 수정·로그아웃 |
| /queue | 12초 대기 시뮬레이션, 일시정지·재개·자동 이동 |
| /admin | 접속량·대기·예약·서버 현황, 예측 그래프, 혼잡 상태 전환 |
| /admin/flights | 예시 운임 수정, 판매 중지/재개, 좌석 현황 조회 |

항공편 상세는 별도 이동 없이 검색 결과의 펼침 영역에서 확인합니다. 관리자 화면은 권한 검증 없이 볼 수 있는 UI 데모이며 실제 운영자 인증 기능이 아닙니다. 좌석 현황은 고정 예시이며 실제 좌석 재고를 관리하거나 예약 간 점유를 공유하지 않습니다.

## 체험 순서

1. 메인에서 조건을 정하고 검색합니다.
2. 운임·상세 보기에서 가는 편을 선택합니다. 왕복이면 오는 편을 반대 방향으로 조회해 해당 편의 운임을 표시합니다. 모의 예약의 총액은 선택한 두 운임의 합계입니다.
3. 임의의 이름, 과거 생년월일, demo@example.com, 010-0000-0000 등의 테스트 연락처를 입력합니다. 국제선 여권 예시는 M12345678입니다.
4. 각 구간에서 인원수만큼 좌석을 고릅니다.
5. 확인 체크 후 체험 결제를 누르면 예약이 생성됩니다. 실제 결제 정보는 입력하지 않습니다.
6. 예약내역에서 상세·취소를 확인하거나 푸터의 관리자 화면 체험 링크로 이동합니다.

각 화면의 '상태 화면 체험'을 펼치면 조회 실패, 좌석 선점 실패, 시간 만료, 결제 실패를 확인할 수 있습니다. 관리자의 항공편 판매 상태는 예시 항공편 목록에 반영됩니다.

## 상태 관리와 제한

수업 스타일의 JavaScript JSX, 함수 컴포넌트, 일반 CSS, useState와 props를 유지했습니다. 여러 화면의 공통 상태 전달을 위해 React Context만 추가했습니다. BookingContext가 예약 초안, 체험 회원, 예약 목록, 항공편 템플릿을 메모리에서 관리합니다. localStorage 등에 개인정보와 비밀번호를 저장하지 않으며 새로고침 시 체험 데이터가 초기화됩니다. 비밀번호 검증이나 이메일 발송은 하지 않습니다.

선택 시간 10분과 좌석표는 화면 체험용입니다. Ignav 여정은 조회 당시의 전체 인원 운임과 통화를 모의 결제까지 유지합니다. 예시 항공편은 기존 등급 배율로 총액을 계산합니다. 예시 운임을 수정하면 이후 검색에 반영되며 이미 선택한 항공편과 완료 예약은 당시 값으로 유지됩니다.

서버 연동 시에는 인증·권한, 좌석 확보·만료·동시성, 가격 재검증, 결제 승인과 예약 확정, 대기열 순서를 모두 백엔드에서 보장해야 합니다. 지금의 프론트엔드 시뮬레이션은 이를 대체하지 않습니다.

- src/pages/: 화면별 컴포넌트
- src/components/FlightSearch.jsx: 검색 폼
- src/components/BookingUI.jsx: 단계 표시, 예약 요약, 선행 단계 보호
- src/data/: 공항·여행지·항공편 예시
- src/utils/: 날짜 검증, 총금액, 탑승객 검증 및 테스트
- server/ignav.js: 로컬 검색 API와 Ignav 연동
- src/App.css, src/Flow.css, src/index.css: 일반 CSS와 반응형

## 수업 저장소 참고

https://github.com/seonghunShin/web4_koreait_react 를 실제 복제해 커밋 cb3a7c0ac8a4f4bd9dac17bc2f632d971edc83b9의 react-basic-app10 App.jsx/main.jsx/RootLayout.jsx/PostForm.jsx/App.css 및 react-basic-app7 App.jsx를 읽었습니다. components/pages/layouts 분리, React Router, useState, 제어 입력 및 일반 CSS 방식을 따랐습니다. TypeScript, Tailwind, Redux는 사용하지 않았습니다.

스카이스캐너 공식 URL은 웹 도구에서 본문이 반환되지 않아 현재 사이트의 상세 화면을 검증하지 못했습니다. 검색 중심 구성에 자체 All is well 디자인을 적용했습니다. 여행지 사진은 Unsplash의 분위기 참고 이미지, 폰트는 Google Fonts이므로 인터넷 연결이 필요합니다. 실패하면 시스템 글꼴과 배경색을 사용합니다.
